# MY儀式

**見るまで確定じゃない。**

結果が出る直前に人が無意識に行う、連打、長押し、なで、隠す、ためらい、余白タップを記録するスマートフォン向けミニゲームです。既存IP・実在ゲーム・実在機種には依存せず、「結果を見る直前の人間あるある」として構成しています。

## デザインテーマ

オープニング、ステージ間、診断結果は「黒魔術＆黒歴史」がテーマです。プレイ中は黒魔術装飾で素材を覆いすぎず、各ステージの疑似体験を優先します。

- `assets/ui/logo_mygishiki.png`：透過済みメインロゴ
- `assets/ui/app_icon_mygishiki.png`：favicon、Apple Touch Icon、Webアプリアイコン、画面内の封印シンボル
- `assets/ogp.png`：OGP画像
- `manifest.webmanifest`：Webアプリ用メタデータ

## 新しいゲーム進行

```text
オープニング
  ↓
今日の本命と音・振動を選択
  ↓
本命以外の4ステージ
  ↓
本命ステージ
  ↓
黒歴史リプレイ
  ↓
診断・本命結果・今日の運勢・詳細ログ
```

各ステージの状態は次の順で進みます。

```text
intro → idle → ritual → resolving → concealed → reveal → win / lose
```

- `intro`：1〜2行の短い導入。タップまたは約2.6秒で開始。本命だけ約3.6秒
- `idle`：操作開始前
- `ritual`：ドラッグや長押しを始めた状態
- `resolving`：リール、捕獲、召喚、照会などの途中演出
- `concealed`：結果は内部で決定済みだが、画面では隠れている状態
- `reveal`：プレイヤーが固有操作で開示した瞬間
- `win` / `lose`：開示後の結果

結果は `resolving` の終了だけでは自動表示されません。必ずプレイヤー自身の開示操作が必要です。

操作対象は透明ホットスポットだけにせず、背景を隠さない薄い破線・矢印・小さな半透明ラベルと、画面下の `1/3 操作 → 2/3 待機 → 3/3 開示` ガイドで示します。ドラッグやスワイプが難しい場合でも一周できるよう、主要操作にはタップ代替があります。

## 今日の本命

オープニング後に、最も当てたいステージを1つ選びます。本命以外の4ステージを先にプレイし、本命を最後に表示します。

本命ステージでは導入時間、枠の装飾、振動を少し強めます。最終画面には本命を独立した枠で表示し、次のようなセッション文脈も反映します。

- 本命成就
- 本命だけ届かず
- 最後の一つが救った
- 本命沈黙

## ステージ操作

### 1. 兆しのランプ

使用画像：

- `assets/stage1_slot_base.png`
- `assets/stage1_slot_spinning.png`
- `assets/stage1_slot_win.png`

操作：

1. ランプを自由になでる
2. レバーを下へドラッグする
3. 3つの停止ボタンをすべて押す
4. concealed状態のランプを指で覆う
5. 指を離して結果を開示する

ランプ上の移動距離、レバーまでの時間、停止順、連打数、ランプを隠した時間を記録します。

### 2. 最後の封印

使用画像：

- `assets/stage2_battle_base.png`
- `assets/stage2_battle_capturing.png`
- `assets/stage2_battle_success.png`
- `assets/stage2_battle_fail.png`

操作：

1. カプセルを上方向へスワイプして投げる
2. 3回揺れる間にA、B、十字キー下、画面を操作する
3. 3回目の後、Aを押す、Bを離す、カプセルをタップする、のいずれかで開示する

A連打は小さな同期震動、B長押しは暗転、十字キー下は沈み込みとして画面へ返します。確率は変わりません。

投擲対象として画面中央下へカプセルと上矢印を表示します。カプセルのタップでも投擲を開始できます。

### 3. 最後の一回

使用画像：

- `assets/stage3_gacha_top.png`
- `assets/stage3_gacha_drawing.png`
- `assets/stage3_gacha_win.png`
- `assets/stage3_gacha_lose.png`

操作：

1. 召喚ボタンを長押しする
2. 指を離して召喚を開始する
3. 閉じた扉を左右へスワイプする
4. 裏向きカードをタップ、または上へスワイプして開示する

ためらい、長押し、なで、扉を途中で止めた回数、カードへの接触を記録します。結果画像上へ虹色の覆いは追加しません。

### 4. 当落のお知らせ

使用画像：

- `assets/stage4_lottery_base.png`
- `assets/stage4_lottery_opening.png`
- `assets/stage4_lottery_win.png`
- `assets/stage4_lottery_lose.png`

操作：

1. 封筒を自由になでる
2. フラップを上へドラッグする
3. 中の紙をゆっくり引き出す
4. 紙を十分に引いた時点で開示する

ドラッグ量と結果画像の表示量を連動させ、途中で止めたり戻したりできます。

結果画像は `clip-path` で隠しますが、操作判定は画像とは独立した `paper-pull` ボタンで受けます。結果画像が完全に隠れている状態でも操作不能になりません。

### 5. 結果照会

使用画像：

- `assets/stage5_exam_base.png`

画像は待機画面だけに使用し、照会中、結果パネル、カーテンはHTML/CSSで実装しています。

操作：

1. 結果表示ボタンを押す
2. 約2.1秒の照会を待つ
3. 結果を覆うカーテンを上へ動かす
4. 必要ならカーテンを戻す
5. 一定以上開いて結果を確定する

## 儀式エコー

前ステージまでの操作傾向を次のステージの装飾へ反映します。説明文では明示しません。

- `mash`：ボタンや痕跡が細かく脈打つ
- `stroke`：指跡のような線が移動する
- `hold`：魔法陣がゆっくり浮かぶ
- `timing`：静止と点滅の間が生まれる
- `hide`：画面端の影が濃くなる
- `escape`：余白タップへ落書きが反応する

儀式エコーは演出だけに使い、当たり確率へは一切影響しません。

## 当たり判定

セッション開始時に `script.js` の `resultPatterns` から勝敗パターンを1つ選びます。パターンは2勝または3勝を中心に構成し、各ステージの長期的な当たり率が約50%になるよう対称にしています。

操作ログ、儀式タイプ、儀式エコーによる確率補正はありません。デバッグ時だけ `?result=win` / `?result=lose` で固定できます。

## 音と振動

本命選択画面で「有効にする」「音なしで始める」を選択できます。設定は `localStorage` の `mygishiki-sound` へ保存します。ゲーム画面右上の `音 ON / 音 OFF` から後で切り替えられます。

外部音源は使わず、Web Audio APIの短い合成音を操作へ割り当てています。振動は `navigator.vibrate()` 対応環境だけで動作します。音なしでも全操作と演出を完了できます。

## 状態管理

現在のステージは `script.js` の `state` で管理します。

```js
{
  status,
  isResolved,
  isRevealed,
  result,
  startedAt,
  resolvedAt,
  revealedAt,
  lastInputAt,
  pointerState,
  interactionLogs
}
```

- 結果はセッション開始時に一度だけ決定
- `isRevealed` で多重開示を防止
- `nextStage()` は開示前に動作しない
- ステージ移動時に登録タイマーを破棄
- Pointer Eventsは現在表示中のDOMへだけ登録
- リスタート時に本命、状態、ログ、タイマーを初期化

## 黒歴史リプレイと診断

結果画面の表示順：

1. 実ログから生成した黒歴史リプレイ
2. 今回もっとも強く観測された儀式
3. 5ステージのタッチヒートマップ
4. MY儀式タイプ、称号、実測値ベースの理由
5. 本命結果
6. 今日の運勢
7. 折りたたみ式の4指標とステージ別詳細ログ

ヒートマップは各ステージ画像上へCanvasを重ね、Pointer Eventsで記録した正規化座標へ半透明円を描画します。同じ場所への接触が多いほど、円が大きく濃くなります。

診断タイプの定義は `typeDefs`、点数計算は `analyzeLogs()`、理由文は `diagnosticReason()` で調整できます。

## 結果シェア

Web Share API対応環境ではOSの共有画面を開きます。非対応環境ではX投稿画面を開き、それも不可能な場合だけクリップボードへコピーします。

共有内容：

- MY儀式タイプ
- 称号
- 最も強い儀式と実測理由
- 本命結果
- 今日の運勢と当たり数
- サブコピーと `#MY儀式`

タッチ座標そのものは共有しません。

## デバッグURL

通常表示ではデバッグUIを一切表示しません。

| パラメータ | 内容 |
|---|---|
| `?debug=1` | ホットスポット、状態、現在ログを表示 |
| `?result=win` | 全結果を当たりへ固定 |
| `?result=lose` | 全結果をハズレへ固定 |
| `?stage=slot` | スロットだけを直接起動 |
| `?stage=capture` / `?stage=ball` | 捕獲だけを直接起動 |
| `?stage=gacha` | ガチャだけを直接起動 |
| `?stage=lottery` / `?stage=mail` | 抽選封筒だけを直接起動 |
| `?stage=exam` | 合否だけを直接起動 |
| `?echo=mash` | 連打エコーを固定 |
| `?echo=hide` | 隠蔽エコーを固定 |

パラメータは併用できます。例：`?debug=1&stage=gacha&result=win&echo=mash`

## モバイル操作

基準サイズは `390 × 844` です。

- ステージ画像は前面を `object-fit: contain` で表示
- 余白は同じ画像の `cover + blur` 背景で補完
- 操作面は `touch-action: none`
- Pointer Eventsの `pointerdown / pointermove / pointerup / pointercancel` を使用
- Pointer Captureでドラッグ中の画面外移動に対応
- 画像ドラッグ、長押し保存、テキスト選択、タップハイライトを抑制
- ホットスポットは通常透明、デバッグ時だけ表示
- ゲーム進行に必須の操作だけは、背景を覆わない薄いガイドとタップ代替を表示

## ローカル実行

静的サイトのためビルドは不要です。

```bash
npx serve .
```

またはApacheなどでプロジェクトルートを配信してください。

JavaScript構文確認：

```bash
node --check script.js
```
